Stop the calls. Route the request.

Workers across Georgia, Florida, Alabama and Tennessee report maintenance problems by calling and texting Tonya and Jordan all day. v1 replaces that one channel — a QR code or a link, one queue, and a one-click forward to the hotel or apartment that actually does the fixing. Nothing else.

Fig 1 — The actual problem

The change isn't tracking. It's who gets interrupted.

Plateau doesn't fix anything — the hotel or the apartment office does. Tonya and Jordan are a routing desk. Today every request arrives as an interruption and has to be retyped from a text thread. v1 doesn't reduce the number of requests; it changes when the coordinators have to deal with them and makes each one arrive complete enough to forward.

Fig 2 — "QR code or a link"

Both. It's one form behind two doors.

A QR code is a link a camera can read — they aren't alternatives, and building both is not two builds. The real question is what the form already knows when it opens. Start with the plain link: it works for every worker on day one, needs no printing and no hotel's permission. Add QR codes for the busiest hotels once the form has proven itself.

Fig 3 — The queue

Four statuses, not eleven

v1 has no task engine, no dependencies, no SLA clock. A request is submitted, forwarded to the right property, confirmed fixed, and closed. Add structure when there's data to justify it — not before.
