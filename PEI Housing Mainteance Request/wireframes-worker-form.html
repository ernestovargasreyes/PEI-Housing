Opening the link

Pick up where you left off

1 The prompt names the problem, room and property so a worker who started two requests, or a foreman on a shared phone, knows which one this is before continuing.

2 Start over is a quiet button under Continue: tapping the larger button by habit keeps the answers instead of throwing them away.

Request that was never sent

1 The title says the request was not sent before anything else: the worker tapped Send and believes it went in.

2 Delete it is a quiet button under Send now, because deleting loses a complete request and sending is what the worker meant to do.

Emergency check

1 · Emergency check

1 Each condition is a full-width row the height of a large button, so one tap with a thumb or a work glove reaches the call screen.

2 The way past the list is a bordered button below it, not a filled one: the eight conditions are read before the button that skips them.

3 The language switch sits in the bar on every screen in the same place, so a Spanish speaker finds it before reading any question.

Call now

1 The call button is the largest control on the screen and the only filled one. There is no Next and no Send.

2 The way back is a text link at the bottom, for a mistaken tap, so it does not compete with the call button.

Should the screen give one line of safety advice per condition, like the gas line drawn here, and who writes and approves those lines?

Where and who

2 · Where are you — plain link

1 The property control opens a full-height list instead of the phone's own dropdown, because the list needs search, state headings and a way out when the place is missing.

2 The apartment number field uses the letter keyboard: apartment numbers such as B12 include letters.

Choose where you're staying

1 Search matches the name and the city, because a worker may know "Magnolia in Valdosta" but not the listing's exact name.

2 "My place isn't listed" is the last row and stays visible when a search finds nothing, so a missing property never stops the request.

My place isn't listed

1 The name field takes whatever the worker calls the place, and the hint names who matches it, so the worker knows a person reads it and does not need the exact listing name.

2 City is optional: a worker who knows the name but not the town can still send the request.

2 · Where are you — from a property QR code

1 The property from the QR code is a card with Change, not a locked field: a sign can be scanned by someone staying at a different property.

2 Only the apartment number is typed.

2 · Where are you — returning worker

1 One Change button for all four details keeps the card a single yes-or-no, and the name on it shows a foreman whose details the phone is holding.

2 The main button repeats the question's answer, so confirming and moving on is one tap. The step count drops to 3 because "Who are you" is skipped.

3 The last request sits below the card and the main button sits below it, so a worker who opened the link only to check on a request sees it went in before tapping anything.

3 · Who are you

1 The reason for the cell number sits under the field: workers are more likely to give a real number when they see maintenance will call before entering.

2 Job site is last and marked optional, so skipping it reads as allowed.

The problem

4 · What's wrong

1 The problem type comes first because it decides who the property sends.

2 The description is required but the hint says a sentence is enough, so the box does not read as a report to write.

3 Photos are last on the screen and upload while the worker moves on, so a weak signal never holds up the next screen.

Might be an emergency

1 The screen quotes the words that matched, so the worker sees why it appeared and can judge a false match ("smell gas" from the stove pilot versus a gas leak).

2 Continuing is a full bordered button, not a text link: going on is a legitimate answer here, unlike on the call screen after a tapped emergency.

Getting in and sending

5 · Getting in

1 Entry comes first on the screen because the answer decides whether the times below are required. Drawn with No selected, so the times are required.

2 The send button says what it does. While photos are still uploading it reads "Sending 1 photo…" and sends when they finish.

6 · Confirmation

1 The request number is the largest text on the screen, with the screenshot line under it, because nothing is texted or emailed at submission.

2 The emergency number repeats here for a problem that gets worse after sending.

3 "Report another problem" is bordered, not filled: finishing is the expected end, and a second problem is the exception.
